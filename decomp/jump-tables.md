# Decompiling Functions with Jump Tables

## What Are Jump Tables?

Jump tables are compiler-generated lookup tables used to implement `switch` statements efficiently. Instead of a series of `if-else` comparisons, the compiler creates an array of addresses - one for each case. The code loads the address from the table based on the switch variable and jumps directly to it.

In SOTN disassembly, jump tables are identified by labels prefixed with:
- `jpt_XXXXXXXX` (used in DRA overlay)
- `jtbl_XXXXXXXX` (used in stage overlays like NO3)

The assembly pattern loads the jump table address and uses `jr` (jump register) to transfer control.

## Handling Jump Tables in Decompilation

### Creating a Scratch on decomp.me

1. Copy the function assembly into the "Target Assembly" field
2. Copy the jump tables **below** the function assembly
3. Add `.section .rodata` before the jump tables

**Example structure:**
```asm
.set noat      /* allow manual use of $at */
.set noreorder /* don't insert nops after branches */

glabel MyFunction
... (function asm continues here)

.section .rodata

glabel jtbl_801A7B40
... (jump table continues)

glabel jtbl_801A7B58
... (jump table continues)
```

The jump tables won't appear in the Target/Current diff panes, but successful decompilation will show `switch` statements.

---

### Adding Decompiled Functions to the Repo

When decompilation is complete, the original `.rodata` jump table must be ignored so the compiler-generated table from your C code is used instead.

#### Step 1: Split Jump Tables in YAML

Use the provided tool to automate splitting:

```bash
# For DRA (uses jpt_ prefix)
python3 tools/split_jpt_yaml/split_jpt_yaml.py \
    config/splat.us.dra.yaml \
    asm/us/dra/data/ \
    jpt_

# For stage overlays like NO3 (uses jtbl_ prefix)
python3 tools/split_jpt_yaml/split_jpt_yaml.py \
    config/splat.us.stno3.yaml \
    asm/us/st/no3/data/ \
    jtbl_
```

Copy the output below `Cut below this line:` into your splat YAML.

#### Step 2: Split the Function into Its Own File

Functions with jump tables must start their own C file. 

**Before:**
```c
// 75F54.c
INCLUDE_ASM("asm/us/dra/nonmatchings/75F54", func_80133960);
INCLUDE_ASM("asm/us/dra/nonmatchings/75F54", func_80133BDC);  // has jump table
INCLUDE_ASM("asm/us/dra/nonmatchings/75F54", func_80133FCC);
```

**After:**
```c
// 75F54.c
INCLUDE_ASM("asm/us/dra/nonmatchings/75F54", func_80133960);

// 93BDC.c (new file)
INCLUDE_ASM("asm/us/dra/nonmatchings/93BDC", func_80133BDC);
INCLUDE_ASM("asm/us/dra/nonmatchings/93BDC", func_80133FCC);
```

#### Step 3: Update the YAML to Ignore Original rodata

Modify the splat YAML to use `.rodata` (with leading dot) to ignore the original table:

```yaml
# before
      - [0x4208C, rodata] # jpt_80133C10
      - [0x420B4, rodata] # jpt_80135058

# after
      - [0x4208C, .rodata, 93BDC] # jpt_80133C10 - ignored, uses 93BDC.c
      - [0x420B4, rodata] # jpt_80135058
```

The `.` prefix tells splat to ignore this segment - the jump table generated by compiling `93BDC.c` will be used instead.

## Summary

| Step | Action |
|------|--------|
| 1 | Identify jump table labels (`jpt_` or `jtbl_`) in disassembly |
| 2 | Include jump tables in decomp.me scratch under `.section .rodata` |
| 3 | Run `split_jpt_yaml.py` tool if not already done for the overlay |
| 4 | Split the function into its own C file |
| 5 | Mark the rodata segment with `.rodata` prefix in YAML to ignore it |
| 6 | Update `INCLUDE_ASM` paths for the new file |
